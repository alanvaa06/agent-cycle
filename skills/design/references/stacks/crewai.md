# CrewAI

## 1. What it is
A Python multi-agent library: an `Agent` (role, goal, backstory, tools, llm) runs a tool-calling loop, `Crew`, `Task` and `Process` orchestrate several agents, and a `Flow` is an event-driven state machine (`@start`, `@listen`, `@router`) whose state can be persisted. Since 1.15.18 a `Flow` can be conversational: `handle_turn(message, session_id=...)` restores the saved state, appends the message and runs a handler; the docs recommend wrapping Agents and Crews in a Flow. Sources: https://docs.crewai.com/v1.15.24/en/guides/flows/conversational-flows.md and https://docs.crewai.com/v1.15.24/en/concepts/production-architecture.md . Version 1.15.24 (released 2026-10-07), MIT, Python >=3.10 and <3.14, independent of LangChain: https://pypi.org/project/crewai/1.15.24/ . 1.15.25 followed the same day as a version bump plus a docs snapshot (two commits in https://github.com/crewAIInc/crewAI/compare/1.15.24...1.15.25 and the notes at https://github.com/crewAIInc/crewAI/releases/tag/1.15.25 ); this card's source facts were read at the 1.15.24 tag. No TypeScript SDK was found (unverified), so `ts_sdk: none`.

Notes on the filter values (each with its own source):
- model_portability: native OpenAI, Anthropic, Gemini, Azure, Bedrock and Snowflake Cortex integrations (`provider/model-id`); every other provider goes through the optional `crewai[litellm]` extra, and the docs say `litellm` was quarantined on PyPI. Sources: https://docs.crewai.com/v1.15.24/en/concepts/llms.md and https://docs.crewai.com/v1.15.24/en/learn/litellm-removal-guide.md
- a2a: `A2AClientConfig` and `A2AServerConfig` (agent card, JWS signing, token auth; `protocol_version` defaults to 0.3.0), installed with `crewai[a2a]`, which pins `a2a-sdk~=0.3.10` (PyPI metadata of 1.15.24). The server side runs each incoming task with `agent.aexecute_task` and no Flow; no HTTP host for it was found in the package source (a search for a2a-sdk server application classes returned nothing) and the page points to AMP for production, so serving it yourself is unverified. Sources: https://docs.crewai.com/v1.15.24/en/learn/a2a-agent-delegation.md and https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai/src/crewai/a2a/utils/task.py
- deploy_constraints: the page labels webhook HITL (`humanInputWebhook` and `/resume`) as Enterprise; the library path (`@human_feedback` with an own provider) has no such label. Source: https://docs.crewai.com/v1.15.24/en/learn/human-in-the-loop.md
- default_egress: the endpoint is `https://telemetry.crewai.com:4319/v1/traces` and `CREWAI_DISABLE_TELEMETRY=true` switches it off (source also reads `CREWAI_DISABLE_TRACKING`); tracing to the CrewAI platform is opt in, and the docs warn traces may contain prompts. Sources: https://docs.crewai.com/v1.15.24/en/telemetry.md , https://docs.crewai.com/v1.15.24/en/observability/tracing.md and https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai-core/src/crewai_core/telemetry.py
- stability: 24 patch releases from 1.15.0 (2026-06-25) to 1.15.24 (2026-10-07), about one per four days, with behavior changes inside patches (1.15.18 promoted conversational flows to stable, 1.15.22 rejects replay when stored tasks differ, 1.15.24 lets a start step re-run on the events it listens to); `A2AConfig` is deprecated for removal in v2.0.0; no published stability policy found (unverified). Sources: https://pypi.org/project/crewai/ , https://github.com/crewAIInc/crewAI/releases and https://docs.crewai.com/v1.15.24/en/learn/a2a-agent-delegation.md

## 3. Seam mapping
| Seam | Support | How | Source |
|---|---|---|---|
| sessions | adapter | Flow persistence defaults to SQLite (`@persist`); the `FlowPersistence` ABC has 3 required methods (`init_db`, `save_state`, `load_state`) and 3 optional pending-feedback ones whose defaults save without the context and return nothing, so HITL has nothing to resume unless they are overridden; no Postgres, Supabase, DynamoDB or Firestore implementation found, so the build writes a small synchronous adapter (inference); memory is a separate system (local LanceDB, OpenAI embedder by default) and is not used | https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai/src/crewai/flow/persistence/base.py and https://docs.crewai.com/v1.15.24/en/concepts/flows.md |
| hitl_gate | adapter | A `PRE_TOOL_CALL` hook blocks a call but the run continues, and any exception other than `HookAborted` is swallowed so the tool runs (fail-open, observed); `@human_feedback` with an own `HumanFeedbackProvider` pauses a flow STEP after its method returns, not a tool call inside the agent loop, and `Flow.from_pending(id).resume(feedback)` continues the same flow execution in a new Flow instance; the build turns a blocked mid-loop call into a flow pause and runs the approved call itself | https://docs.crewai.com/v1.15.24/en/learn/tool-hooks.md and https://docs.crewai.com/v1.15.24/en/learn/human-feedback-in-flows.md |
| step_cap | custom | `max_iter` (docs say default 20, 25 at runtime) counts tool-executing rounds, not model calls; at the cap the agent gets one more model call for a best answer and returns it as a normal result, with no exception or outcome signal; the count restarts on every `kickoff`, so a resume restarts it; the binding counts model calls in a `PRE_MODEL_CALL` hook | https://docs.crewai.com/v1.15.24/en/concepts/agents.md and https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai/src/crewai/experimental/agent_executor.py |
| tool_call_cap | custom | No native per-run tool-call cap found (`max_usage_count` is per tool; how it is set is unverified); the binding counts in a `PRE_TOOL_CALL` hook, which runs once per call before that call's body | https://docs.crewai.com/v1.15.24/en/learn/tool-hooks.md and https://docs.crewai.com/v1.15.24/en/concepts/tools.md |
| model_provider | native | `provider/model-id` strings for the native providers; `base_url` for OpenAI-compatible endpoints; other providers through the optional LiteLLM extra | https://docs.crewai.com/v1.15.24/en/concepts/llms.md |
| telemetry | adapter | OpenInference `CrewAIInstrumentor` or OpenLIT send OTLP to an own backend; GenAI semantic conventions are not mentioned in any CrewAI page read; the library's own telemetry runs on a private TracerProvider | https://docs.crewai.com/v1.15.24/en/observability/arize-phoenix.md and https://docs.crewai.com/v1.15.24/en/observability/openlit.md |

## 4. Known traps
- [data] Anonymous telemetry is ON by default and sends to `telemetry.crewai.com:4319`; set `CREWAI_DISABLE_TELEMETRY=true` (source also honors `CREWAI_DISABLE_TRACKING`), never `OTEL_SDK_DISABLED` (it also silences your own OTel SDK), and note an unrecognized value such as "maybe" leaves telemetry ON (observed). Source: https://docs.crewai.com/v1.15.24/en/telemetry.md and https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai-core/src/crewai_core/telemetry.py
- [data] Built-in tracing uploads to the paid CrewAI platform when enabled; a run with no explicit setting buffers spans in memory (up to 1,000 spans or 8 MiB) and on a terminal asks for consent, so set `CREWAI_TRACING_ENABLED=false` and `tracing=False` explicitly. Source: https://docs.crewai.com/v1.15.24/en/observability/tracing.md and https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai/src/crewai/execution.py
- [data] A Flow auto-creates a `Memory` (local LanceDB, OpenAI `text-embedding-3-large` embeddings by default) and a verbose run outside CI asks PyPI for a newer version (`CREWAI_DISABLE_VERSION_CHECK=true` stops it). Source: https://docs.crewai.com/v1.15.24/en/concepts/memory.md , https://docs.crewai.com/v1.15.24/en/learn/human-feedback-in-flows.md and https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai/src/crewai/events/utils/console_formatter.py
- [security] Hooks fail open: any exception other than `HookAborted` is swallowed and the tool runs, and a blocked call does not stop the run, so a gate must catch everything and raise `HookAborted`, and must also block when no turn state is bound. Source: https://docs.crewai.com/v1.15.24/en/learn/tool-hooks.md and https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai/src/crewai/hooks/dispatch.py
- [ops] `@human_feedback` pauses a flow step, not a tool call inside the agent loop; without `provider=` it blocks on console `input()`, and with `emit` every free-text answer costs an extra, non-deterministic LLM call to pick an outcome. Source: https://docs.crewai.com/v1.15.24/en/learn/human-feedback-in-flows.md and https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai/src/crewai/flow/runtime/__init__.py
- [ops] On resume the framework clears the pending row BEFORE it runs the listeners that follow the approval, so a crash there cannot be resumed again unless the adapter makes `clear_pending_feedback` a no-op (observed). Source: https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai/src/crewai/flow/runtime/__init__.py
- [ops] `max_iter` is not the spec's step: it counts tool rounds, its exit is a model-written answer with no failure signal, and it restarts on every `kickoff`. Source: https://docs.crewai.com/v1.15.24/en/concepts/agents.md and https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai/src/crewai/experimental/agent_executor.py
- [ops] Never run two turns concurrently on one Flow instance; the queue (key = session key) serializes turns and every run builds a fresh Flow. Source: https://docs.crewai.com/v1.15.24/en/guides/flows/conversational-flows.md
- [ops] A tool that raises is shown to the model as `Error executing tool: <exception text>` and invites a retry; tools must catch their backend errors and return the spec's error observation. Source: https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai/src/crewai/experimental/agent_executor.py
- [security] MCP: a string reference by slug resolves against the CrewAI platform catalog and URL query strings put keys in the URL; model-visible tool names are prefixed by the server URL or command (stdio names are truncated and hashed, observed); unreachable servers are skipped silently. Use structured configs with a static allow-list. Source: https://docs.crewai.com/v1.15.24/en/mcp/overview.md
- [security] The native A2A server path runs `agent.aexecute_task` outside any queue, session key or approval pause; with the gate installed it blocks every tool (observed), so gated agents need an own `a2a-sdk` server in front of the queue. Source: https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai/src/crewai/a2a/utils/task.py
- [security] `crewai[litellm]` pulls in `litellm`, which the docs say was quarantined on PyPI; pin it exactly with hashes and use native providers where possible. Source: https://docs.crewai.com/v1.15.24/en/learn/litellm-removal-guide.md
- [churn] 24 patch releases in about 104 days with behavior changes inside patches and v2.0 removals announced (`A2AConfig`); pin the exact version and re-run every spike on any upgrade. Source: https://github.com/crewAIInc/crewAI/releases and https://docs.crewai.com/v1.15.24/en/learn/a2a-agent-delegation.md

## 5. Pick when / avoid when
Pick when a native A2A client matters (multi-agent systems on a VPS; server building blocks exist, https://docs.crewai.com/v1.15.24/en/learn/a2a-agent-delegation.md ) and chat turns fit `handle_turn(message, session_id)` on a persisted Flow (https://docs.crewai.com/v1.15.24/en/guides/flows/conversational-flows.md ), with native OpenAI, Anthropic or Gemini SDKs and no LiteLLM (https://docs.crewai.com/v1.15.24/en/concepts/llms.md ). The build still owns the Postgres adapter, the gate, both caps and the telemetry switch-off.
Avoid when patch-level behavior changes cannot be absorbed (https://github.com/crewAIInc/crewAI/releases ) or native OTel GenAI spans are required (none mentioned: https://docs.crewai.com/v1.15.24/en/observability/openlit.md ). Weigh against it when the design has gated tools: the pause is flow-step level and the hook gate fails open, so the gate, the pause and the approved-call execution are binding code (https://docs.crewai.com/v1.15.24/en/learn/tool-hooks.md ). Avoid when no data may leave until the kill switches are proven, since telemetry is ON by default (https://docs.crewai.com/v1.15.24/en/telemetry.md ), or when the library itself must serve A2A under an approval gate without AMP (https://raw.githubusercontent.com/crewAIInc/crewAI/1.15.24/lib/crewai/src/crewai/a2a/utils/task.py ).
